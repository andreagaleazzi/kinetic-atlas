# index.html architecture

Map of the single-file app. `index.html` is the source of truth: if this page and the code disagree, the code wins and this page gets fixed. Lines are thousands of characters long, so find a name with `grep -o '.\{80\}name.\{80\}' index.html`, not by reading lines. Before changing something, check [change-impact.md](change-impact.md).

Last checked against the code: 2026-11-23, commit `ca2bea3`.

## Layout

`<head><style>` → one hidden SVG icon sprite (`<symbol id="i-…">`) → markup (`<main id="top">`, plus `<dialog id="profileDialog">`, `<dialog id="scienceDialog">` and `<dialog id="legalDialog">`, the privacy, GDPR, cookie, terms, accessibility and contact text opened from the footer) → one `<script>` holding a strict-mode IIFE. No globals leak out.

## Inside the script, in order

1. **Constants and presets.** `KEY='kinetic-atlas-offline-v2'` (storage key), `defaults` (profile), and `P`, the drink/product presets. Presets are **positional arrays**, not objects, and the layout differs by type: alcohol and caffeine use `[id, label, volume, abv|mg, group]`, while nicotine adds duration and absorption fields and keeps its group at index 6. `setEntryType` / `assignPreset` / `getFormDose` read them by index. With no explicit preset, `setEntryType` starts from `lastAdded(type)`: the newest entry of that type by the creation time inside its id, only if under 7 days old, else the generic default (`pint45`, `espresso`, `cig`). Nicotine pouches are one `pouch` row plus the `POUCH` table (`{brand: [mg,…]}`, filled into `#pouchBrand` / `#pouchMg` by `fillPouch`); the brand only sets the label and mg. `presetData` maps the legacy ids `pouch3`…`pouch12` in old saved entries to that row. Also here: `TYPES`, `REGIONS`, `LIMITS`, `TONES`.
2. **State.** `state = {profile, profileSet, entries[]}`, plus UI vars (`entryType`, `chartType`, `plotScale`, `horizon`, `series`, `historyStack`, `editId`, `dupOpen`, `lawRef`, `bloodOn`). `bloodOn` (the Nicotine tab's Blood level toggle) is a display preference: it lives in its own `localStorage` key, `BLOOD_KEY`, not in `state`, so exports and undo don't carry it. `chartType` is a compound or `'all'` (the Combined tab, drawn by `drawCombined` on a relative 0–1 or log-mg axis per `plotScale`), so it does not always index a series. Every mutation goes through `transaction(fn)`, which pushes an undo snapshot (max 10), calls `persist()`, then `renderAll()`.
3. **Trust boundaries.** `validateEntry` and `normalizeProfile` clamp and validate everything loaded from storage or JSON import. Import is capped at 2 MB. These define the de facto data schema and become the server-side validation later.
4. **PK model** (pure functions):
   - `instantAmount` / `amountFor`: one-compartment model with first-order absorption (`ka`) and elimination (`ke = ln2/half-life`). Intake is spread evenly over `durationMin`, except pouches (`pouchAmount`, below).
   - `alcoholScenario`: the absorbed ethanol fraction (`absorbedFrac`) is converted to BAC with Widmark `r`, then reduced at a constant `beta` %/h down to 0.
   - `buildSeries(now)`: a 5-minute grid from −96 h to +72 h. Each point holds a central `v` plus `low` and `high` uncertainty bands. Alcohol bands come from r ±0.06 and the clearance range; caffeine and nicotine bands from half-life ×0.7 and ×1.5. Each point also holds `nicBlood`, the same shape in ng/mL, computed whether or not the toggle is on.
   - `at`, `peakNext` and `settledTime` interpolate and query `series`.
   - Pouches: release from the pouch is two-phase, `pouchRel(min) = Σ a × (1 − e^(−min/τ))` over `POUCH_PH` (a fast wash-out and slow diffusion). `pouchF` rounds it into absorbed %, set when Duration changes on a pouch and still editable. `pouchAmount` (used by `amountFor` for any entry where `isPouch` is true) feeds the dose in at the release rate until removal, through the mouth lining at `POUCH_KA` (the pouch row's ka), then one compartment. It ignores the entry's stored `ka`.
   - Blood nicotine: `nicBloodNg(fast, slow, half, kg)` turns two one-compartment sums into venous ng/mL for a blood + tissue (two-compartment) model. `fast` is `amountFor` summed at the 7-minute initial half-life (`NIC_FAST`), `slow` is the body-mg value. The weights come from `NIC_V` (2.6 L/kg), `NIC_VC` (1.3 L/kg), `NIC_FAST` and the terminal half-life. Because it reuses `amountFor`, pouches, spread entries and boluses enter exactly as they do for the mg curve. `amountFor` nudges `ke` when it equals `ka`, for every caller.
   - Test: `node tests/pk.test.js` lifts this block out of `index.html` (between the `// Linear first-order absorption` comment and `function absorbedFrac`) and checks the blood curve against a step-by-step simulation. Keep those two markers, or update the test.
5. **Dates and times.** `profile.clock` (`'24h'` default, or `'12h'`) drives every displayed time through `displayTime` / `tf()` / `tickLab` / `hm`. Date and time entry uses plain text fields, not native pickers (their format follows the OS locale): `#entryDate` + `#entryClock` in Log intake, `#pBed` / `#pWake` in Profile, parsed by `parseDate` / `parseClock`. The entry time is read and written only through `getEntryTime()` / `setEntryTime(ms)`. `setEntryTime` remembers its value (`entryMs`) so `getEntryTime` can return the second occurrence of a repeated hour when the clocks go back; `clearEdit` re-runs `setEntryType` after an edit or duplicate so the form drops that entry's preset. Stored values: entry `time` is ISO, `bed` / `wake` are 24h `HH:MM`.
6. **Rendering.** `renderAll` recomputes `series`, writes the summary metrics, sleep badges and `#profileHint` inline, then calls `renderChart` (hand-drawn `<canvas>`, DPR-aware, no chart library), `renderHistory`, `renderLedger`, `renderInterpretation` and `renderLaw`. HTML is built from template strings; interpolated user text goes through `esc()`. Icons come from the sprite via `ic(name)` (or `<svg class="ic" aria-hidden="true"><use href="#i-name"/>` in static markup). `renderChart` draws dose markers in the gutter under the x-axis (`doseMarks`) and adds the nearby doses to `#chartTooltip`. With `bloodOn` on the Nicotine tab it also draws `nicBlood` as a dotted curve on a right-hand axis and widens `pad.r` for the labels. `renderInterpretation` hides `#guideSec` unless a card applies to the current data. A `setInterval` runs `renderAll` every 60 s while the tab is visible.
7. **Wiring.** `addEventListener` calls near the bottom, using delegated clicks (`data-action`, `data-close`). History rows offer `edit`, `duplicate` and `delete`; `duplicateEntry` reuses `editEntry`'s prefill and then clears `editId`. Export/import is `exportJSON` (`{app, version:2, profile, entries}`) and `exportCSV`. `exportPNG` saves the chart as shown and labels the image from the DOM (`.legend` spans, `#plotUnit`, `#plotNote`).

## Entry shape (also the future DB row)

`{id, type: 'alcohol'|'caffeine'|'nicotine', preset, label, time: ISO string, note, qty, durationMin, dose, ka, ...}`, plus type-specific fields: alcohol `units, volume, abv, food`; caffeine `mg, volume`; nicotine `mg, fraction`. IDs are generated on the client.

## Region and legal lines

`profile.region` (default `'uk'`) only picks which `REGIONS` entry `renderLaw` shows in `#sciLaw` (drink-driving limits, legal age, drinking guideline, emergency number, sources). It is reference text: it does not change the model, the UK unit counts or the UK guidance cards.

`LIMITS` holds the legal BAC lines per jurisdiction (`[BAC %, canvas label, legal effect]`, plus a `note` for zero-tolerance rules that can't be drawn). The `#lawRef` menu above the alcohol chart sets `lawRef`: `''` keeps the default .05/.08/.15 effect lines, and a jurisdiction id swaps them for its legal lines, adds the `#lawKey` explanation under the chart and adds the jurisdiction to `#plotUnit` (so `exportPNG` labels it).

## Science dialog

`#scienceDialog` lists the model parameters, guidance thresholds (EFSA caffeine limits, UK units), cited sources, the pouch parameters and brand strengths (`#sciPouch`), the blood-level model and how well it fits (`#sciBlood`), the region text (`#sciLaw`) and a "Data handling" block that promises no outbound requests and local-only storage.
